Model scorecard

NO JARGON ZONE
ML in 60 seconds.

A tiny field guide so the charts don't look like mysterious modern art.

🌳 Decision Tree

A flowchart of yes/no questions. It splits customers using rules, like: “Was there a recent payment delay?” Easy to explain, can overfit.

📍 KNN

Looks at the most similar customers in the training data. If most nearby customers defaulted, it predicts default. Scaling matters because distance is the whole trick.

🌲 Random Forest

A crowd of decision trees votes on the answer. Usually more stable than one tree, but harder to explain tree by tree.

🧮 Confusion Matrix

A scoreboard of correct and incorrect predictions. Rows are the real answer; columns are the model's prediction.

🎯 Precision

When the model predicts default, how often is it right? Higher precision means fewer false alarms.

🚨 Recall

Out of all actual defaults, how many did the model catch? Higher recall means fewer missed risky cases.

⚖️ F1-score

A balance between precision and recall. Useful when the classes are uneven.

📈 ROC-AUC

How well the model ranks default cases above non-default cases across thresholds. Closer to 1 is better; 0.5 is coin-flip territory.

Our evaluation setup: stratified 80/20 train-test split, random_state=42. KNN uses StandardScaler. Decision Tree and Random Forest use class weighting. Test set has 4,673 non-default and 1,327 default cases.

A note on responsible ML

This dataset includes demographic features such as sex, age, education, and marital status. They can introduce fairness concerns. This is an educational experiment, not a production credit decision system. A real deployment needs fairness testing, legal review, monitoring, and human oversight.
